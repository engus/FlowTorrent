# Выбор Windows-пакета после переноса в workspace

В [первом полном CI-прогоне](https://github.com/engus/FlowTorrent/actions/runs/40516333124) прошли тесты приложения Windows, Clippy и проверка лицензий. Создание установщика остановилось до компиляции: Cargo отклонил виртуальный корневой манифест для `cargo rustc --bin flowtorrent`. В отличие от используемого сборщиком пакетов `cargo build`, эта команда требует явного выбора пакета в корне виртуального workspace.

Команда сборки с ресурсами теперь выбирает `--package flowtorrent`; сохранены locked release-сборка, Windows target, два jobs, статический CRT и скомпилированный ресурс значка/версии. Тест выполняет настоящую команду на виртуальном workspace без зависимостей, добавляя `--print=cfg` для проверки выбора пакета и target без Windows SDK и линковки. Используются Rust 1.92.0 и offline-режим. До исправления тест воспроизвёл ту же ошибку виртуального манифеста, после — прошёл; локально прошли все 49 тестов скриптов.

Rust-движок/UI, прототип AppKit, зависимости, разрешения workflow и настройка загрузки установщиков не менялись. Нативная сборка установщика и проверка сохранности данных при установке/переустановке/удалении должны пройти на новой закоммиченной ревизии в CI. Успешные проверки приложения и ARM-пакет первого прогона не заменяют этот Windows-результат. Релиз не публикуется.
