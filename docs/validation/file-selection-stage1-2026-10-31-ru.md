## Поведение

- Чекбоксы файлов в нижней панели одного торрента; при проверке, восстановлении ошибки и занятости изменения заблокированы. Контроллер повторно проверяет устойчивый ID файла и торрента.
- Отдельные команды применяются к актуальному манифесту. Останавливается только этот торрент, сохраняется намерение, меняется набор файлов остановленного librqbit и возвращается запуск только при намерении Active. После завершения выбранной части можно включить ранее исключённые файлы, снова открывая закреплённые дескрипторы для записи.
- Отключение сохраняет данные и проверенные куски. Общие пограничные куски могут содержать байты исключённых файлов. Пустой выбор остаётся со статусом «Файлы не выбраны», нулевым прогрессом выбранных данных, без уведомления о завершении и надписи «Скачано» вместо ETA. Новое добавление по-прежнему требует хотя бы один файл.
- Манифест версии 1 читается; изменение выбора переводит его в версию 2, допускающую пустой набор. Старый клиент должен отклонить её без перезаписи. Восстановление остаётся остановленным до окончания проверки. Флаг уведомления не сбрасывается: не более одного на торрент.
- Ошибка до записи оставляет прежний выбор. Неоднозначная ошибка после замены сверяется с диском; обнаруженный новый выбор остаётся остановленным с ошибкой, «Повторить» заново обеспечивает сохранение перед восстановлением. Неизвестное/повреждённое состояние блокирует запись до перезапуска/восстановления. При ошибке изменения в движке устаревший выбор также нельзя запустить.
- Удаление из списка сохраняет данные. Корзина учитывает все закреплённые принадлежащие приложению файлы без padding, включая отключённые, пустые и пограничные данные; проверки идентичности/жёстких ссылок и чужие файлы сохраняются. Успешное удаление очищает маркер восстановления перед повторным добавлением.

## Обзор и регрессионные тесты

Независимый обзор всей ветки нашёл четыре P2: удаление остановленного пустого торрента, старый маркер восстановления после повторного добавления, неоднозначную ошибку после замены манифеста, надпись «Скачано» при пустом выборе. Все воспроизведены до исправления и покрывающие тесты прошли после него. Тест отрисованного Slint-виджета 1280×720 дополнительно воспроизвёл оставшийся снятым чекбокс при неотправленной команде; теперь он возвращается к сохранённому выбору, а отключённый контрол ничего не отправляет. Второй обзор или слова проверяющего не заменяют тесты.

Также проверены быстрые последовательные команды, неверные/повторные ID, сохранение запуска/остановки, ошибки записи и Retry, пустой выбор после перезапуска, отсутствие ложного уведомления, повторное использование проверенных данных, пограничные куски, отключение/включение при настоящей передаче с ограниченной скоростью, Корзина с сохранением чужого файла.

## Ограничения и следующие шаги

CI/runtime Windows x64 и Mac Intel и физическая проверка чекбокса не запускались. Общий код Rust/Slint использует закреплённый API движка и прежние дескрипторы с ограниченными правами; это работа по совместимости исходников, не доказательство исполнения на этих платформах. Lifecycle probe — интеграционная проверка, не ручная проверка Finder/Dock/Retina. Длительные ресурсные тесты и большая публичная сеть этим стендом не доказываются. Настоящие приоритеты остаются этапом 2, чекбоксы их не имитируют. Коммиты, push, merge и публикация не выполняются.
