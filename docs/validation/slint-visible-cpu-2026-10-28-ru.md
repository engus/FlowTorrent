# CPU при видимом окне — 28 октября 2026 года

## Метод

По просьбе автора исследованы короткие показания CPU 9–17% без прерывания ночного теста. Исходники `142f2bb75a4c4c8769f15a44d0f4fface33406b0`, неизменённая библиотека приложения, release, программный рендерер, macOS 27.2 / 26B123, Apple Silicon, масштаб 2. PID изолированного клиента — 10245. Источник, получатель, драйвер и caffeinate продолжали работать. Окно, торренты, скорости, исполняемый файл, настройки и зависимости не менялись.

Сделаны два read-only профиля `/usr/bin/sample` по десять секунд с интервалом пять миллисекунд. Отчёты и время находятся в игнорируемой `_work/validation/overnight-20261027/cpu-investigation/`. Общий интервал в `profile-window.json` нужно исключить из обычного сравнения CPU: профилирование добавляет нагрузку. Отладчик, перезапуск, дополнительный рой и смена рендерера не использовались.

## Результат

Оба профиля показывают горячий путь через `WinitWindowAdapter::draw`, `WinitSoftwareRenderer::render`, фиксацию транзакции CoreAnimation, `CA::Render::copy_image` и преобразование цветов CoreGraphics/vImage. Также видны обход сцены, текст и растеризация SVG. Обработка снимков состояния встречается значительно реже: считать форматирование строк основной причиной эти данные не позволяют.

| Включающие потомков выборки стека | Профиль 1 | Профиль 2 |
| --- | ---: | ---: |
| Отрисовка окна Winit | 141 | 157 |
| CoreAnimation copy_image | 103 | 110 |
| Растеризация SVG в Slint | 9 | 13 |
| UiState::apply | 0 | 3 |
| UiState::refresh_view | 0 | 2 |

Это включающие потомков количества выборок, а не проценты CPU и не число кадров. Отсутствие функции в коротком профиле не означает нулевую стоимость. Ранее сопоставленные фоновые интервалы пяти загрузок дали около 0,67% и 0,66% одного ядра и медианы footprint 54,72 и 54,92 МиБ. Видимые и скрытые фазы, изменения размера окна и профилирование в итоговом отчёте следует разделять.

Причина высокой стоимости кадра подтверждается исходниками точных версий зависимостей:

- `softbuffer 0.4.8`, `src/backends/cg.rs`, `buffer_mut` создаёт новый обнулённый массив пикселей размером `width * height`.
- `BufferInterface::age()` возвращает ноль. Slint 1.18.1 в `renderer/sw.rs` выбирает `RepaintBufferType::NewBuffer`, поэтому переиспользовать этот буфер для частичной перерисовки не получается.
- `present_with_damage(self, _damage)` игнорирует изменённые прямоугольники и вызывает `present()`: создаётся целый CGImage и заменяется содержимое CALayer. На этой границе профили показывают копирование и преобразование цветов.
- Retina 2× даёт четыре физических пикселя на логический. Размер полного 32-битного буфера растёт с физической площадью окна. Это создаёт дополнительную временную нагрузку на память, но само по себе не объясняет безопасным образом весь рост RAM и не исключает утечку.

Контроллер публикует состояние раз в 500 мс, видимый UI применяет снимки и обновляет модели. Сравнение старых и новых строк уже есть, неизменившиеся строки не заменяются. Свойства Slint также сравнивают значения до пометки зависимостей изменёнными. Поэтому утверждать, что любое повторное присваивание одинакового значения вызывает перерисовку, неверно. Скорости, прогресс и другие изменения отображения всё же могут запускать дорогие кадры. Число кадров, изменённые области и вклад каждого поля в этом прогоне не инструментировались.

## Следующие эксперименты — пока не реализованы

1. В отдельном кандидате объединить обновления видимой статистики и передавать только значимые изменения отображения, сохранив немедленные команды, ошибки и смену состояния. Сравнить CPU при одинаковых размере окна и нагрузке, проверить отзывчивость.
2. Измерить число кадров, изменённые области и работу SVG-кеша до изменения иконок. SVG в этих профилях вторичен относительно основного найденного пути.
3. Если вывод кадра останется главным потребителем, отдельно сравнить поддерживаемый GPU-рендерер Mac с программным, включая RAM и размер пакета. Закреплённые версии, поведение Windows и прототип AppKit сохранять без изменений до отдельного решения.

Исправление и снижение CPU не заявляются. Ночной тест продолжает работать; восемь часов пока не подтверждены. Коммитов, пуша, тегов, загрузки установщиков и публикации релиза не было.
