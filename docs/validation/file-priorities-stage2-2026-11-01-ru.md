## Поведение и патч

У каждого файла список Low / Normal / High («Низкий / Обычный / Высокий»), рядом с чекбоксом или второй строкой в узком окне. Normal — значение по умолчанию. Исключение сохраняет приоритет; его настройка не включает файл. Устойчивые ID и блокировка при проверке/ошибке/занятости защищают изменения; отказ отправки/ошибка возвращает сохранённое значение виджета.

Новые запросы предпочитают выбранные High, Normal, Low; внутри уровня — имена. Отключённый владелец не повышает приоритет общего куска; отсутствие High не блокирует доступный Low. Все выбранные файлы входят в завершение. Это не отдельная полоса и не очередь торрентов. Изменение кратко останавливает/переподключает торрент и может повторно запросить незавершённые куски; проверенные данные сохраняются. Само ранжирование в установившемся режиме запросы не отменяет.

Редкие переопределения хранятся в v3; v1/v2 читаются как Normal, чекбокс не понижает v3. Восстановление задаёт нативный порядок до запуска. Неизвестные уровни, дубли, padding/неизвестные ID, повреждённые/будущие данные отклоняются. Начальное добавление через контроллер остаётся с Normal; переданные заранее приоритеты отклоняются до захвата файлов, чтобы не применить несохранённую политику.

`vendor/librqbit` — точный 9.0.1, SHA256 архива `4349c0f35ede576a87cc2881dc6eb286ff7a1c8fc4d1f7fef95b5c5a530a7174`, исходные лицензии сохранены. Отличаются только три Rust-файла: session.rs, torrent_state/mod.rs и torrent_state/live/mod.rs. [Описание](../../vendor/librqbit/PATCHES.md). Версии не обновлялись; Cargo.lock только заменяет registry source/checksum локальным источником. Хранилище/сеть/приватность/нативный код и патчи LSD/bencode не менялись. Persistence/fastresume выключены; флаг уведомления не сбрасывается.

## Проверки

Rust 1.92.0, locked, jobs 2, Mac deployment 14.0, отдельный target; контролируемые loopback-стенды. Логи, журнал и 367 отпечатков исходников/входов сборки: игнорируемая `_work/validation/file-priorities-20261101/`.

- До исправлений обзора: полный прогон 184 пройдено, 0 ошибок/пропусков. Release намеренно прерван после замечаний; это история, не финальное доказательство.
- Финальные fmt, rustfmt патча и строгий Clippy для всех targets: пройдены.
- Финальный полный набор тестов: **187 пройдено, 0 ошибок, 0 пропусков** (41 итог harness).
- Обычный release: ошибка загрузки `zerofrom_derive` (E0463/E0432), как в этапе 1; лог сохранён. Release с локальным `--config 'profile.release.build-override.strip="none"'`: **пройден**, 2 мин 03 с. Файлы профиля Cargo для обхода не менялись.
- `cargo run --locked --example macos_lifecycle_probe -j 2`: **пройден** (delegate, порядок файловых callback, reopen/modal lease и скрытый цикл событий).
- Locked offline metadata зависимостей и `check_ringbuf_exception.py`: **пройдены**; librqbit использует локальный 9.0.1, версии не менялись.

Все 367 входов остались побайтово неизменными при финальной проверке. SHA256 release-бинарника: `cb8ca13c9973e52b831b22f9a4ce5d0aa604e4ba1b6357b6df93c564828604cf`. Коды выхода/отпечатки сохранены рядом с `completed.json`.

Независимый обзор нашёл P1: завершение другого торрента могло перезаписать неизвестное третье намерение в режиме read-only. Инъекция завершения воспроизвела ошибку до исправления и прошла после. Read-only также блокирует центральное сохранение и автоматический запуск после Checking по старому намерению (отдельный RED/GREEN). Независимо воспроизведено расхождение начального приоритета с манифестом; исправлено явным отказом. P2 обзора исправляет неточное обещание не прерывать запросы: описана остановка при изменении. Все шесть тестов контроллера проходят, включая исключение/перезапуск/схему, ошибки до/после замены и отказ движка/Retry. Инъекции не доказывают настоящую передачу.

Настоящие передачи доказывают предпочтение High, смену порядка, полное равенство данных и обход отсутствующего High к доступному Low. Последний стенд проверяет нулевые проверенные байты High у источника; первоначальный источник со всеми верными данными был неподходящим контролем, не доказательством. Построение порядка проверяет равные уровни, неверные входы и общие куски исключённых файлов. Отрисованные тесты Slint проверяют широкий/узкий список, занятость и откат неотправленной команды.
