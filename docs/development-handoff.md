# Продолжение разработки FlowTorrent

Состояние на 21 октября 2026 года. По просьбе автора работа остановлена после сохранения текущего результата. Релиз 1.0 ещё не готов.

Основная реализация этапов 1–8 выполнена: движок, безопасное добавление `.torrent`, четыре настройки, управление загрузками, восстановление сессии, Slint UI, фоновая работа, один экземпляр, уведомления и ошибки. Непройденные ручные проверки в плане остаются открытыми.

[CI этапа 8](https://github.com/engus/FlowTorrent/actions/runs/39619141807) прошёл Windows x64, Mac ARM и Mac Intel. Исправление LSD на Mac сохраняется.

## Последние изменения

В начале этапа 9 добавлены четыре воспроизводящих теста и исправления:

- отказ команды сохраняет исходную ошибку повреждённой сессии;
- чрезмерно вложенный bencode отклоняется до рекурсивного разбора;
- завершённый файл на Windows восстанавливается при открытом внешнем читателе;
- повтор после реальной ошибки совместного доступа с немедленной паузой не оставляет бесконечную проверку.

Четыре теста `reliability`, форматирование и clippy по всем targets без предупреждений прошли. Общий локальный прогон тестов остановлен после длительной параллельной линковки; полный набор для этих изменений пока не считается пройденным. Проверить CI завершающего коммита. Следующую локальную сборку выполнять с ограничением параллелизма: `cargo test --locked --all-targets -j 2`.

При завершении обнаружены повреждённые локальные index/указатель main и два документа, заполненные нулями. Сначала сделана отдельная копия рабочих файлов; Git восстановлен по последнему отправленному `0ed37da`, документы восстановлены из Git и истории текущей работы. Причина повреждения не установлена.

## С чего продолжить

1. Прочитать [спецификацию](spec-1.0.md), [план](superpowers/plans/2026-10-21-flowtorrent-1.0.md) и [фактические проверки](engineering-validation.md). Проверить последний CI. Продолжать этап 9, не повторять этапы 1–8.
2. Закончить проверки пропадания/возврата сети, повреждённых кусков, управляемой ошибки записи/ENOSPC и выбора файлов на границе кусков. Сначала изучить существующие тесты восстановления, недоступного тома и аварийных границ.
3. Добавить измерительный harness и `docs/performance.md`: пустое окно, пять активных торрентов, двадцать записей, скрытое окно. Seeder должен быть отдельным процессом: текущий GUI smoke совмещает роли и не годится для измерения памяти клиента.
4. Провести длительную загрузку/раздачу, сон/пробуждение; заполнить release checklist фактическими результатами. Изучить число открытых файлов на Mac и существующий `librqbit::try_increase_nofile_limit()`, копирование больших preview; оптимизировать после измерений. Проверить стабильность IPC namespace при будущих обновлениях Rust (`DefaultHasher`).
5. Этап 10: установщик Windows, `.app`/DMG для двух архитектур Mac, ассоциация `.torrent`, лицензии, версии и контрольные суммы. Автоматическая публикация GitHub Release не разрешена. Установщиков пока нет.

Остаются ручные проверки масштаба Windows 100/125/150/200%, клавиатурного добавления через системный диалог, реального меню трея, установленной ассоциации файлов; Finder/Dock/Cmd+Q/Retina на настоящем Mac. AppKit probe в CI их не заменяет.

Доставка и запрет системных уведомлений проверяются после упаковки: Windows shortcut должен иметь `com.engus.flowtorrent`, Mac — соответствующий bundle ID. Сертификаты Windows и Apple Developer ID/notarization не предоставлены. Ночной прогон, измерения ресурсов, чистая установка/обновление/удаление ещё не выполнены. Свежий обзор всей ветки — после завершения плана.

## Зафиксированные решения

Rust 1.92, librqbit 9.0.1, Slint 1.18.1. Четыре настройки: папка, уведомления, общий лимит загрузки и отдачи. По умолчанию скорость не ограничена; минимальный включённый лимит — 0,02 МБ/с. После скачивания продолжается раздача; её останавливает «Пауза». MIT автора сохраняется вместе с лицензиями зависимостей.

```powershell
cargo fmt --all -- --check
cargo clippy --locked --all-targets -j 2 -- -D warnings
cargo test --locked --all-targets -j 2
cargo build --locked --release -j 2
```

Cargo на текущей машине: `C:\Users\Engus\.cargo\bin`. Иногда upstream Slint build script получает PermissionDenied при перезаписи `target/debug/build/SLINT_DEFAULT_STYLE.txt`. После полного завершения Cargo можно удалить только этот проверенный шестибайтный сгенерированный файл со значением `fluent` и повторить команду. Не менять ACL или защиту системы.
