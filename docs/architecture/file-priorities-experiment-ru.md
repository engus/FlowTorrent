# Эксперимент приоритетов файлов — этап 2

> Согласованное [продолжение от 2 ноября](priority-menus-experiment-ru.md) заменяет списки значками/контекстным меню и добавляет независимый приоритет торрента. Ниже сохранено описание этапа 2.

Пользователь одобрил полный эксперимент из двух этапов и запросил Low / Normal / High в `experiments/file-priorities`. Выбор файлов первого этапа сохраняется. Дополнение действует только в этой ветке, не меняя релизный main и эксперименты AppKit/производительности.

По умолчанию у каждого файла без padding приоритет Normal. Начальный диалог добавления остаётся только с Normal; контроллер отклоняет переданные заранее переопределения, чтобы не применить отсутствующую в манифесте политику. Компактный список рядом с чекбоксом применяет изменения сразу. Отключение сохраняет приоритет, включение возвращает его. Приоритет исключённого файла можно настроить без включения. При проверке/ошибке/занятости управление заблокировано. Команда использует ID файла, не индекс видимой строки.

Приоритет задаёт предпочтение новых запросов кусков внутри одного торрента: High, затем Normal, затем Low; внутри уровня — порядок имён. Отсутствующие у пира приоритетные куски не блокируют доступные менее приоритетные. В установившемся режиме ранжирование не отменяет отправленные запросы. Применение изменения кратко останавливает торрент: незавершённые куски могут быть отменены и запрошены снова, проверенные куски используются повторно; общий пограничный кусок получает приоритет самого приоритетного выбранного файла. Это не распределение полосы и не очередь между торрентами.

Используется точный пакет librqbit 9.0.1 с описанным локальным vendor-патчем: проверяемый полный порядок файлов, установка до передачи, сохранение при остановке/запуске и использование существующим планировщиком. Стандартный порядок и безопасное хранилище не меняются. Версии зависимостей не обновляются. Уровни приоритетов остаются в приложении. Имитация через постоянное изменение выбора файлов нарушила бы смысл завершения/данных, поэтому отвергнута; обновление движка вне этого эксперимента.

Редкие переопределения отличного от Normal приоритета сохраняются по FileId в манифесте v3; v1/v2 читаются как Normal. Неизвестные уровни, дубли, padding/неизвестные ID и будущая схема отклоняются без перезаписи. Переключение файлов не понижает v3. Восстановление настраивает приоритет остановленного торрента до запуска после Checking. Гарантии сохранения намерения, сверки ошибок и Retry остаются как в этапе 1. Уведомление остаётся однократным.

Тесты доказывают настоящий приоритет High на локальной передаче/запросах кусков, последующее завершение Low, равные уровни/стандартный порядок, изменения при остановке/передаче, восстановление, сохранение приоритета исключённого файла, неверные входы, ошибки после сохранения и ID/откат UI. Требуется совместимость исходников Windows/Intel; локальное исполнение Mac не заменяет CI и физическую проверку.
