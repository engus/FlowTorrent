# План приоритетов файлов

> Исполнять в текущем чате через executing-plans и test-driven-development, с одним независимым финальным обзором. Сохранить работу; без коммитов/push/merge.

**Цель:** настоящие Low / Normal / High, сохранение и управление Slint.
**Архитектура:** редкие переопределения приложения -> устойчивый полный порядок -> малый vendor-патч закреплённого librqbit -> существующий планировщик. Повторно использовать сохранение политики остановленного торрента из этапа 1.
**Технологии:** Rust 1.92.0, librqbit 9.0.1, Slint 1.18.1, Mac deployment 14.0, locked и -j2.
**Спецификация:** [одобренное расширение](../../architecture/file-priorities-experiment-ru.md).

- [x] RED->GREEN хранилища/домена: v3, старые Normal, сохранность дублей/неверных/будущих данных.
- [x] RED->GREEN движка: происхождение vendor, проверка полного порядка и сохранение при остановке/восстановлении; настоящие High-first / Low-completes, равные уровни и доступность кусков.
- [x] RED->GREEN контроллера: сохранение приоритета через общую транзакцию; выбор не понижает схему, приоритет исключённого файла сохраняется, восстановление до запуска, ошибки и Retry.
- [x] RED->GREEN UI: локализованный список, настоящий ID, блокировка при занятости/проверке/ошибке, откат неотправленной команды.
- [x] fmt, строгий Clippy, все тесты, release, lifecycle Mac; независимый обзор, воспроизводимые исправления и парные отчёты. Main/AppKit/другие эксперименты не меняются.

Фокус обзора: старые/будущие/повреждённые поля; общие и отсутствующие приоритетные куски; устаревшие ID/отказ списка; блокировки active/paused/initializing; неоднозначное сохранение/Retry/удаление/добавление; сохранение при отключении/проверке; безопасное хранилище, приватные стенды, границы платформ.
