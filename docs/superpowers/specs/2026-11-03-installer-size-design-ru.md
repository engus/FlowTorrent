# Эксперимент с размером установщиков

Запрошен отдельный эксперимент без удаления функций, со сравнением размера и производительности и без публикации. Это исследовательская ветка, а не разрешение переносить оптимизацию в main.

База: main 9714c4bf0129988977746a3c469b6e843340d9dd, пакеты Actions 41516995085. Код Rust/UI, ресурсы, Cargo.lock, Cargo features, обработка panic, минимальные ОС и полные лицензии сохраняются.

Сравним обычный release с более плотной упаковкой (ULMO/LZMA для DMG и solid LZMA2/ultra64 для Inno), затем отдельный профиль compact: opt-level=s, fat LTO, strip=symbols, один codegen unit. Это выбранные исполнителем параметры эксперимента, а не обещанный оптимум. Удаление функций, зависимостей и смена panic исключены.

Для каждого пакета сохраняются профиль, формат сжатия, ревизия, хеш Cargo.lock, размер и SHA-256. На одном CI runner последовательно выполняется A/B/B/A: два наблюдения каждого профиля в пяти сценариях, software renderer, фактический scale, прогрев 20 секунд и 15 отсчётов. Сохраняются исходные CSV, окружение, CPU, разные нативные метрики памяти и проверенный прогресс. Ограничение передачи 655360 Б/с проверяет ресурсы при одинаковой работе, а не максимальную скорость сети. Windows-проба использует прежний динамический CRT, установщик — статический; это явно отмечается как ограничение. Результаты разных runner и разные метрики не смешиваются. Физическая приёмка и ночной тест этим не закрываются.

Release не меняется. В CI выполняются существующие debug-проверки, compact-тесты всех targets, Mac lifecycle и упаковочные проверки. Windows проверяет сохранение данных при установке/переустановке/удалении на одноразовом runner. Release, теги, merge в main и сайт не публикуются. Тестовые артефакты сохраняются для проверки, как в согласованной базовой сборке.

Используется управляемый worktree experiments/installer-size; исходный main и незакоммиченные отчёты не меняются. Локальный Cargo отсутствует, свободного места мало, поэтому Rust-проверки выполняются в CI. Workflow-файлы сохраняются; эксперимент запускается через упаковочные скрипты и существующую точку входа ресурсных проверок в этой ветке. Одиночные ресурсные проверки остаются доступны явно. Решение о переносе результатов в main принимается отдельно.
