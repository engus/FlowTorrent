# Native UI polish — user request, 27 October

The user confirmed that the tray switch and hidden-window icon work and requested a real restart check plus five concrete UI corrections. This is an explicit change to the earlier sidebar/add-pane/menu presentation. Shared engine, persistence, ownership and Trash rules remain binding; preserve Windows compatibility and the isolated AppKit prototype. No release, tags or installer uploads.

- Verify the ordinary Mac app restores a saved disabled tray switch after graceful Quit/relaunch. Restore the original enabled choice afterward. Do not alter transfer intent, login, notification permission, folder or rate settings.
- Use a native template image for the Mac menu-bar logo: monochrome, automatically white/dark according to the system background. Keep the Dock/app and Windows tray branding colored.
- Restore right-click actions on torrent rows: Start/Stop/Retry as appropriate, Open folder, Copy magnet, Remove entry, Torrent and files to Trash. Use stable IDs and existing confirmation/command paths. Right-click on an already selected row preserves multi-selection; an unselected row becomes the target. Ellipsis still opens the details drawer. No implicit transfer action on selection.
- Replace the expanded sidebar TORRENTS heading with a 24-logical-pixel color brand symbol, vertically aligned with the collapse button. Preserve the 56-pixel collapsed rail and current header height.
- Mac menu statistics use one disabled summary item: `↓ <download> · ↑ <upload> · <localized Downloading>: <count>`. Preserve current aggregate semantics, tooltip detail, locale updates and event-driven hidden refresh. Windows tray layout can retain its existing presentation.
- Replace the inline magnet/preview pages with one separate owned Slint window, above and modal to the main window, while the main list stays visible. Add-file still uses the native picker; magnet input transitions to the existing folder/file preview inside the same add window. Cancel/Escape/close cancel the current add; close is blocked during a committing command. Reuse current selection, no-clobber preparation and asynchronous commands. The folder picker must belong to the add window. Successful add closes it; queued previews cannot receive stale callbacks from an earlier torrent. Native ownership must not make it globally always-on-top.

Implementation choices: keep the existing pinned Slint/Winit and platform crates. Use an AppKit document sheet and a disabled Win32 owner for native modality, with deterministic cleanup; do not block the Slint loop with a nested modal run loop or introduce polling. Dialog defaults around 640×560 logical pixels, resizable with a scrollable file body and pinned actions. Theme/language mirror the main window. Recreate between distinct queued preview IDs; preserve the magnet→preview transition. A window-scoped callback verifies the preview identity before dispatch.

Alternatives: retaining the inline page would not satisfy the requested separate window; an in-window overlay would not provide native ownership. A new UI framework would enlarge scope and break the shared Slint intent. The native child-window approach is the implementation choice for this explicit request.
